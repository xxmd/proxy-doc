# 01 · VLESS / XTLS-Vision / REALITY 各干什么

这三个词不是并列的三个协议，而是**三层叠加**的东西。很多人把它们放在一起比较，其实它们各管一件事。

```
┌──────────────────────────────────────────────────────┐
│  你的真实流量（访问 google.com 等）                    │
├──────────────────────────────────────────────────────┤
│  ③ REALITY   「装成谁」 —— TLS 层伪装 + 抗主动探测      │
│             让探测者看到的是目标大站                    │
├──────────────────────────────────────────────────────┤
│  ② Vision    「怎么走」 —— 数据流填充 + TLS 记录对齐    │
│             消除 TLS-in-TLS 的指纹特征                  │
├──────────────────────────────────────────────────────┤
│  ① VLESS     「说什么」 —— 极简无状态的代理协议         │
│             告诉服务端"我要连哪个目标"，承载数据         │
├──────────────────────────────────────────────────────┤
│  TCP 443                                              │
└──────────────────────────────────────────────────────┘
```

| 组件 | 所在层 | 一句话职责 | 解决的核心问题 |
|---|---|---|---|
| **VLESS** | 应用层协议 | 极简信封，说明收件人地址 | 替代 VMess，去掉多余加密和特征 |
| **XTLS-Vision** | 数据流处理 | 填充 + 按 TLS 记录边界对齐 | **TLS in TLS 特征** |
| **REALITY** | TLS 层 | 偷真实大站的握手 | **主动探测** + 免域名免证书 |

---

## ① VLESS —— 信封格式（"说什么"）

VMess 的继任者，一个**极简、无状态**的代理协议。负责在隧道建立后告诉服务端「我要连 `www.google.com:443`」，然后双向搬运数据。

**关键设计：它自己不加密**（配置里 `"decryption": "none"`）。这不是偷工减料，而是分层哲学：

| | VMess | VLESS |
|---|---|---|
| 自带加密 | ✅ 有 | ❌ 无（交给 TLS） |
| 双重加密开销 | 有 | 无 |
| 时间戳校验 | 有（时钟不同步直接失败） | 无 |
| 协议头大小 | 较大 | 极小 |

**类比**：VLESS 是信封上写地址的规范 —— 规定"收件人写在哪一栏"，但信封本身不防偷看，防偷看是外层 TLS 的事。

> ⚠️ 所以**裸 VLESS（不带 TLS）是明文的**，绝对不能单独用。

`flow: xtls-rprx-vision` 这个字段就是用来启用下面的 Vision 的。

---

## ② XTLS-Vision —— 包装技巧（"怎么走"）

要解决的问题叫 **TLS in TLS**：

```
你的客户端 ──[TLS ①：你到 google]──> google.com     ← 内层 TLS
     └── 这整条流量，又要塞进 ──[TLS ②：你到代理服务器]──> VPS
```

内层的 ClientHello / ServerHello 是长度极其固定的二进制块，在隧道里呈现非常规律的**包长分布和时序特征**。GFW 不需要解密，只看包长和节奏就能判断"这个 TLS 隧道里在跑 TLS 握手" → 代理 → 封。

**Vision 做的事：**

1. **按 TLS 记录边界对齐** —— 让内层记录直接对应外层记录，消除"套娃"造成的长度参差
2. **首包填充（padding）** —— 让连接初期的包长分布更像正常浏览器
3. 仅对握手阶段特殊处理，数据阶段仍高效转发

**XTLS 的思想脉络**：传统代理对所有数据"解密→再加密"，费 CPU 又留特征。XTLS 让部分数据**直接转发（splice）**，Vision 是第三代实现。

**类比**：Vision 是打包手法 —— 让包裹外观尺寸和普通快递毫无区别。

> ⚠️ Vision 只支持**纯净入站**，不能和其它协议/回落混用。官方强调「只配置 XTLS Vision，不兼容普通 TLS 代理」。

## ③ REALITY —— 身份伪装（"装成谁"）

### 它解决的问题

传统 TLS 代理（Trojan、VLESS+TLS）有四个软肋：

1. 需要自己的域名
2. 需要自己的证书（还得续期 —— 就是 `gost` 那套最容易踩的坑）
3. 需要真网站做回落，否则探测者发个 `GET /` 就露馅
4. 域名在 CT 日志里公开可查

### 做法：不自己签证书，直接"偷"真实大站的握手

```
【合法客户端】
ClientHello: SNI = <目标大站> + 用 REALITY 公钥构造的认证信息
        ↓
你的服务器 :443
   ├─ 用 REALITY 私钥校验：✅ 通过
   ├─ 与客户端用 REALITY 密钥对协商会话密钥
   ├─ 把目标站的真实证书链原样取回来给客户端（所以证书是真的）
   └─ 进入 VLESS 协议，正常代理

【探测者 / 普通浏览器】
ClientHello: SNI = <目标大站>
        ↓
你的服务器 :443
   ├─ 校验：❌ 失败（没有 REALITY 公钥）
   └─ 把整个连接原样转发给真正的目标站
      → 探测者看到：真证书 + 真网站 + 真响应，毫无破绽
```

**本质：对探测者而言，你的服务器就是目标站的一台端口转发器。**

### 三个附带好处

| 好处 | 说明 |
|---|---|
| **不需要域名** | 省掉买域名、配 DNS |
| **不需要证书** | 省掉 ACME 续期的全部麻烦 |
| **强制 uTLS** | 服务端限制客户端必须用浏览器 TLS 指纹 |

### target 的选择（很容易踩坑）

| 要求 | 原因 |
|---|---|
| 支持 **TLS 1.3** | REALITY 只工作在 TLS 1.3 |
| **稳定、地理邻近、同 ASN 优先** | 每次握手都要连它取证书；官方建议「从同一 ASN 借证书」 |
| ❌ 避开 **apple / icloud** | Xray 二进制明确警告会被 GFW 针对 |
| ❌ 避开 **Cloudflare 后面的站** | 未认证流量会被转发过去，你的服务器会变成 CF 的免费加速节点 |
| ❌ 不要用被墙域名 | 握手直接失败 |
| ❌ 不要用国内域名 | 产生回国流量，一眼 REALITY |

**实测**：`www.microsoft.com` 在 Xray 26.x 上会导致所有客户端握手失败，详见 `03-排错记录.md`。

## 顺带：Xray 是什么

**Xray 是"实现这些协议的程序"，不是协议本身。**

| 层面 | 例子 | 类比 |
|---|---|---|
| 协议（规则） | VLESS、Vision、REALITY、Trojan | HTTP 是协议 |
| 实现（程序） | **Xray**、mihomo、sing-box、gost | nginx 是 HTTP 的实现 |

```
gost  之于  http+tls / socks5
Xray  之于  VLESS / VMess / Trojan / REALITY
        ↑ 同一个性质：一个二进制，跑在服务器上，把某种代理协议实现出来
```

同一个 Xray 二进制**既能当服务端也能当客户端**，区别只在配置（`inbounds` 还是 `outbounds`）—— 和 gost 的 `-L` / `-F` 一样。

服务端用 Xray，客户端用 Clash Verge（mihomo 内核）—— 这是目前最主流的组合，两边的 REALITY 实现是互通的。

## 四个常见误区

| ❌ 误解 | ✅ 事实 |
|---|---|
| "REALITY 加密更强" | 不改变加密强度（还是 TLS 1.3），改变的是**可识别性** |
| "Vision 是一种加密" | Vision 是**流处理/填充**，不提供任何加密 |
| "VLESS 不加密所以不安全" | 分层设计，安全由外层 TLS 提供；但裸 VLESS 确实是明文 |
| "配了 REALITY 就 100% 不被封" | 官方明确否认：**IP 层面照样会被封**，邻居波及、流量模型都能封你 |

---

## 一句话类比

把它想成**寄一份机密文件**：

- **VLESS** = 信封上的书写规范
- **Vision** = 打包手法（让包裹外观和普通快递毫无区别）
- **REALITY** = 借用一家大公司的名义和公章（有人来查，看到的是"这确实是那家公司的包裹"—— 因为真的是从那边原样拿回来的）
