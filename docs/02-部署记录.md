## 服务端配置要点

`/usr/local/etc/xray/config.json`（完整内容见 `server/xray-config.json`）

| 配置项 | 值 | 说明 |
|---|---|---|
| 入站协议 | `vless` + `flow: xtls-rprx-vision` | VLESS 信封 + Vision 消指纹 |
| 端口 | `443/tcp` | 最不惹眼 |
| 传输安全 | `reality` | 借用目标大站的 TLS 握手 |
| `dest` / `serverNames` | 一个香港本地站点 | 必须先通过 `test-reality-targets.sh` 验证 |
| `shortIds` | 16 位十六进制 | 8 字节，长度必须为偶数 |
| 出站 | `freedom`（`domainStrategy: UseIPv4`）+ `blackhole` | |
| 路由 | `geosite:cn` / `geoip:cn` / `geoip:private` → **block** | **严禁回国流量** |
| 路由 | `bittorrent` → block | |
| policy | `handshake: 3` / `connIdle: 180` | 避开默认值 60/300 的指纹 |

### systemd 覆盖项

安装脚本创建的 unit **没有**设置 `XRAY_LOCATION_ASSET`，导致 `geoip:cn` 这类规则找不到数据文件。需要额外加：

```ini
# /etc/systemd/system/xray.service.d/10-asset.conf
[Service]
Environment=XRAY_LOCATION_ASSET=/usr/local/share/xray
```

### 系统调优

```
net.core.default_qdisc = fq
net.ipv4.tcp_congestion_control = bbr
net.core.rmem_max / wmem_max = 33554432
net.ipv4.tcp_rmem / tcp_wmem = 4096 131072 33554432 等
net.ipv4.tcp_mtu_probing = 1
net.ipv4.tcp_slow_start_after_idle = 0
```

**BBR 是自建代理性价比最高的一项优化** —— 跨境链路一旦有丢包，CUBIC 会崩，BBR 不会。

## 部署步骤（可复现）

```bash
# 1. 装 unzip（官方脚本的前置依赖，Ubuntu 最小镜像没有）
apt-get update -qq && apt-get install -y -qq unzip

# 2. 装 Xray
curl -fsSL -o /tmp/xray-install.sh https://github.com/XTLS/Xray-install/raw/main/install-release.sh
bash /tmp/xray-install.sh install

# 3. 生成密钥
xray x25519          # PrivateKey + Password (PublicKey)
xray uuid            # 客户端 id
openssl rand -hex 8  # shortId

# 4. 选 REALITY target（关键！不要跳过）
bash test-reality-targets.sh

# 5. 填入配置后一键部署
scp server/xray-config.json server/xray-setup.sh root@<SERVER_IP>:/tmp/
ssh root@<SERVER_IP> "bash /tmp/xray-setup.sh /tmp/xray-config.json"

# 6. 全链路验证
ssh root@<SERVER_IP> "bash /tmp/xray-verify.sh"
```

## 密钥生成备忘

```bash
# 生成密钥对
xray x25519
#   PrivateKey:            <私钥>  ← 填服务端 realitySettings.privateKey
#   Password (PublicKey):  <公钥>  ← 填客户端 reality-opts.public-key

# 从私钥反推公钥（校验用）
xray x25519 -i "<私钥>"
```

> ⚠️ Xray 新版把客户端这个字段从 `publicKey` **改名成了 `password`**（服务端仍是 `privateKey`）。
> mihomo 客户端里仍叫 `public-key`。别被名字搞混。

## 重建清单

万一服务器被封需要换机，按顺序做：

1. 新机器装 `unzip` + Xray
2. `xray x25519` 生成**新的**密钥对（旧的可能已泄露）
3. `bash test-reality-targets.sh` 重新选一个可用的 target
4. 更新 `server/xray-config.json`（新私钥 + 新 target）
5. 跑 `xray-setup.sh` 部署
6. 跑 `xray-verify.sh` 验证
7. 更新 `client/clash-hk.yaml`（新 IP + 新公钥 + 新 target）
8. 客户端重新导入

**整个过程约 10 分钟。** 把这个仓库 clone 到新机器上就够了 —— 凭据都在 `docs/04-完整配置信息.md` 里。
